04 — AUTOMATIC USB NEXT
=======================

Once v0.1 works, the manual WebTILP steps get removed.

KNOWN-WORKING ARCHITECTURE
--------------------------
A recent open-source project called "nspire_codex_remoter" uses a TI-Nspire CX
II + Ndless as a computer remote. It exchanges sequenced, CRC-protected mailbox
files over TI's native USB file-transfer protocol and uses libnspire on the host.

That validates the architecture we want:
  Calculator -> uplink mailbox -> USB -> host
  Host -> AI -> downlink mailbox -> USB -> calculator

WHY NOT START THERE?
--------------------
Because it adds Rust, libusb, libnspire, drivers, calculator code, and AI at the
same time. If it fails you don't know which layer is broken.

V0.2 PLAN
---------
- Replace manual request.tns download with libnspire receive.
- Replace manual response.tns upload with libnspire send.
- Keep sequence IDs.
- Add atomic temp-file + rename writes.
- Add retry/ack behavior.
- Add answer paging/scrolling on calculator.

REFERENCE:
  https://github.com/gfhdhytghd/nspire_codex_remoter

Its README states that it uses the native TI file-transfer USB protocol and
libnspire on the host. We should reuse that proven pattern rather than invent a
raw USB endpoint.
